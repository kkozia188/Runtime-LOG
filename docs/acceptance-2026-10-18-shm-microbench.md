# 共享内存微基准（PRD 10.3，2026-10-18）

## 条件

- 工控机 `5.15.0-1032-realtime`，隔离核 CPU14；控制栈已有序停止（CPU14 上没有用户态线程）。
- 写入者 `shm_bench`：绑 CPU14、SCHED_FIFO 80、`mlockall`、1 kHz 绝对定时；每周期经指针表拷贝 N 个 double
  （模拟读取状态接口）进环并提交。每组 120 s（12 万周期），2000 槽。
- 读者 `tools/shm_read_bench.py`：CPU 0/2/4、nice 10，每 50 ms 批量读取。
- 7 轴档 40 个字段（槽 384 B）；25 轴档 375 个字段（槽 3 KB，按 f64 计，比 PRD 的紧凑类型估计更大）。

## 结论

- **写入耗时达标**：25 轴 p99.9 = 0.37 µs，最大 4.7 µs（目标 ≤ 5 µs）；7 轴 p99.9 < 0.1 µs。
  有无读者，写入耗时没有差别。最大值约 4.4 µs 在四组都出现，与读者无关（推测为偶发的冷缓存或中断）。
- **读者**：两种尺寸都没有缺口，每 50 ms 一批最多 1.2 ms。
- **需要在接入时继续观察**：有读者时，唤醒延迟大于 5 µs 的周期从约 150 增加到约 260（占 0.12% → 0.22%），
  25 轴档最大值从 6.3 µs 变为 8.3 µs。每组只跑了一次，可能是波动，也可能是读者的内存访问造成的。
  这项按 PRD 10.3 在接入实机后的 A/B 中用真实控制循环复核；若确认，先降低读频率或改用紧凑字段类型。

可以进入记录控制器接入。

## 复现

`tools/shm_microbench.sh <out_dir> 120`（ar 用户，realtime 组；脚本会拒绝在 CPU14 仍有用户 FIFO 线程时运行）。
