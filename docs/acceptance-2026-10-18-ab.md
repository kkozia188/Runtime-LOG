# A/B 验收：Runtime-LOG 对 1 kHz 控制周期的影响（2026-10-18）

## 条件

- 台架 Alfa_V3-bench-01，左臂 7 轴 ZeroErr，`bench_left_arm` 运动 scope，1 kHz，驱动 OP、**失能**、无人操作。
- 工控机内核 `5.15.0-1032-realtime`，隔离核 CPU14。RT 线程 `ros2_control_node` tid 274719，FIFO 80，只允许 CPU14。
- 测量：独立 tracefs instance，只在 CPU14 上记录 `sched_switch`；RT 线程相邻两次切入 CPU 的间隔即周期。
  读取进程绑在 CPU0。四组相同的追踪开销，组间可比。
- 每组 180 s（约 18 万个周期）。组前后各读一次 `ethercat master` 计数。
- 工具：`tools/ab_jitter.sh <out> 180 off log0 log1 log5`，`tools/ab_analyze.py <out>`。

| 组 | Runtime-LOG | 主站轮询 |
| --- | --- | --- |
| off | 服务停止 | - |
| log0 | 运行（日志跟随、/proc 1 Hz、内核日志） | 0 |
| log1 | 运行 | 1 Hz（`master` + `slaves`） |
| log5 | 运行 | 5 Hz |

## 结果

| 组 | 周期数 | 均值 µs | 标准差 µs | 最小/最大 µs | 偏差 p99 / p99.9 / 最大 µs | 偏差 >50 µs | 丢帧 / 发送错误增量 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| off | 180002 | 1000.0 | 0.506 | 992 / 1008 | 3 / 4 / 8 | 0 | 0 / 0 |
| log0 | 180002 | 1000.0 | 0.502 | 993 / 1007 | 3 / 4 / 7 | 0 | 0 / 0 |
| log1 | 180002 | 1000.0 | 0.503 | 992 / 1008 | 3 / 4 / 8 | 0 | 0 / 0 |
| log5 | 180002 | 1000.0 | 0.508 | 990 / 1010 | 3 / 4 / 10 | 0 | 0 / 0 |

- 四组标准差、p99、p99.9 相同；最大偏差 7–10 µs 是单个极值，在组间噪声内。
- CPU14 污染：四组都没有用户态外来进程（含 Runtime-LOG）切入 CPU14。切入 CPU14 的只有 idle、
  `irq_work/14`、`rcuc/14`、`ksoftirqd/14` 与 IgH 主站内核线程 `EtherCAT-OP`（约 2 kHz，主站自身绑定）。
- 主站帧：每组发送/接收帧增量与窗口时长一致（每毫秒 1 帧），丢帧与发送错误增量均为 0。

## 结论

PASS：Runtime-LOG 按默认设置（启动期 5 Hz、稳定期 1 Hz 主站轮询，/proc 1 Hz）运行，
对 RT 线程周期、CPU14 和 EtherCAT 帧均无可测影响。服务已切到默认设置。

## 边界

- 测量时驱动失能、无运动；使能运动时 RT 线程负载更高，本次未覆盖。
- 指标是调度切入时刻，不是 DC 同步误差；DC 误差需要读从站寄存器，会发总线报文，本次不做。
